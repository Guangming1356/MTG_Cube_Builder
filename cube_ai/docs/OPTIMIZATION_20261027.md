# 2026-10-27 · Forge 分配与类共享研究

## Problem

依据真实 Java 采样，寻找能降低 Forge 战斗预测计算与内存分配的优化。采用条件同时包含行为检查、通用场景回退和后续原生验证；局部微基准改善不能代替整体效果。

## Inputs

固定 Forge 2.0.15、Java 21.0.12.1 与已核验摘要的 ECJ。原始 JAR、相同源码重编译及候选分开比较。容器源码来自固定官方提交；原始四局 JFR 与日志保留，所有研究在私有目录进行，没有新增模型训练样本。

## Checks performed

- 全局容量实验：四个对照，每组三种固定种子、共六万次变更/复制/迭代/序列化等操作；预设 16 个新 JVM、336 条测量。
- 已知大小构造实验：三个对照，增加空值与单元素等入口检查；固定 12 个新 JVM、396 条长循环测量，源文件、编译类和原始结果摘要复核。
- 类共享预检：两组三阶段，均使用原类字节、正常初始化后退出。根据 Java 的类路径要求，将桥接/兼容目录包装为私有 JAR；第二组增加临时 ASCII 路径联接，退出后核对并非递归移除联接，目标文件保留。
- 继续用有界事件读取分析既有 JFR，没有重打比赛。区分外层过滤上下文、最近调用点和实际分配，避免把整个预测的分配量归到一个容器。采样分配权重不等于保留堆或精确 CPU 时间。

## Findings

| 候选 | 局部观察 | 决定 |
|---|---|---|
| 全局零初始容量 | 单元素分配 104→72 字节，8 元素 104→256 字节，混合分配增加约 9.8% | stop，不采用 |
| 首次分配五元素 | 单/双元素 104→88 字节，8 元素 104→192 字节，混合增加约 2.1% | stop，不采用 |
| 已知大小复制/单元素 | 局部分配下降约 31%–46%，操作轨迹一致；空集合 CPU 中位数增加约 14.7%，通用过滤增加约 11.1%，超出每场景 10% 门槛 | stop，不采用 |
| 应用类共享 | 原中文路径没有共享 Forge 核心类；临时 ASCII 路径下确认额外共享 1,221 类，其中 382 个 Forge 类，含 FModel | 仅可行性通过，未采用 |

第一轮容量实验的短 CPU 循环出现零中位数，原汇总器除零失败。保留失败及原始数据，CPU 门槛记为未知；分配门槛已独立失败，没有补跑来挽救候选。第二轮预先固定更长循环，CPU 回退门槛仍未通过，未以局部复制变快替代整体验证。

类共享的 ASCII 包装预检中，一次对照约 9.103 秒，共享约 8.829 秒；私有内存约 964.25 与 965.58 MiB。每项仅一次且顺序固定，不能作为速度结论。原路径训练有 Unsupported location 警告；ASCII 路径成功支持路径兼容性假设，但包装 JAR 时间戳也不同，这不是唯一根因的严格证明。类共享要求与归档身份限制见 [Java 21 官方文档](https://docs.oracle.com/en/java/javase/21/docs/specs/man/java.html)。

官方后续提交也出现了合并重复战斗预测的实现，但同时修改新版 Monte Carlo AI 和调度策略，不能整段视为 2.0.15 的等价性能补丁。已核对 [官方提交](https://github.com/Card-Forge/forge/commit/e5a0f8156da70ffc7866f923bed371c0111707cd) 及当前版本的危险判断调用点，尚未移植。

## Decision

本轮没有改变默认引擎、规则、AI、JVM 设置或应用源码；继续使用已发布 0.2.5。没有因为研究完成而发布新应用版本。原始失败和个人资料保留，临时 ASCII 联接入口已移除。

## Risks

合成集合比例不代表全部实际牌局；有限操作检查不证明完整 API 等价。CPU 数据有计时粒度和布局波动，未通过门槛不等于所有机器都必然回退。类共享仅验证初始化，没有证明原生事件等价、稳定吞吐量或便携路径可用。这里没有新的胜率、真人娱乐性或色组均衡结论。

## Next actions

优先调查实际高频空集合复制。采样与固定源码显示，CardState 的静态异能/替代效应读取会构造 FCollection 副本。需保留独立快照与后续关键字更新行为，先评估复制构造中的空源快速路径，保持其他方法不变。若有值得继续的原型，重新冻结微基准与原生对照；不得放宽本轮门槛或复用失败样本凑通过。

## Artifacts

完整记录仅在本机 cube_ai/private/role-audit-20261022 下：collection-capacity-trial、known-constructor-trial、cds-preflight、cds-ascii-preflight、native-jfr-probe-v2 与 native-ai-inspection。分别保存协议、候选源码/类、原始测量、采样、摘要及决定。分享包不包含这些研究输出和个人历史资料。本轮只运行独立原型与预检；0.2.5 已发布的 491 项应用回归结论不能用来证明这些实验引擎可用。

## 0.2.6：空复制实测与测速参考检查

### Problem / Inputs

原生日志复核发现两类不同问题：同一配置重复对局可能真的改变事件；阻挡声明也可能仅因 Forge 的 HashMap 遍历而交换句子显示顺序。自动测速原先只要求候选与第一轮参考一致，可能在参考自身不稳定时仍采用其他配置。

另一个独立实验仅跳过 FCollection 复制空列表时的 addAll，保留目标集合、原始嵌套类及所有其他行为。固定同一 Java、Forge JAR、编译器，分别测原始类、原源码重新编译类和候选类；实验代码没有进入正式版本。

### Checks performed / Findings

- 空复制微基准：18 个全新 JVM，702 条结果；每种实现进行 60,000 次语义操作及可变空副本、空参数、子类覆盖检查。语义摘要一致，预先固定的微基准门槛全部通过。空复制分配 64→48 字节，CPU 中位数 9.69→7.81 ns/op；其他大小仍分别核对，不能用局部收益代表整局收益。
- 原生小规模筛选：6 组固定牌组/种子，覆盖 Bracket 2、3、4；A-B-B-A 共 24 局，全部正常完成，禁用缓存、无引擎回退。两次批次中位耗时 100.835→96.697 秒，约降低 4.1%，低于预定 5% 门槛；每进程私有内存没有改善。旧参考事件也未全部一致。结论为不采用，不补跑或替换失败案例。
- 差异复核：两轮候选均与当前第一轮原始实现的 6 局事件一致。第二轮原始实现有一局只改变同一次阻挡声明中两句完整语句的显示顺序；另一个旧参考差异涉及真实对象实例/阻挡/伤害，仍按不同对局处理。原筛选的失败记录保持不变。
- 新回归先在旧实现上复现错误采用，再验证修复。应用全量 513 项通过，网页脚本语法检查通过。隔离浏览器验收使用明确标记的固定对局桩：第 2 轮参考改变伤害后，共执行 12 个桩对局即停止，仅保留 1 个配置的记录，原测速配置逐字节不变，无浏览器警告或错误；这不是 12 局真实 Forge 实战。

### Decision

**发布 0.2.6 的测速验证修复；不发布实验 Java 类，不改变默认 AI、JVM 参数、选牌策略或强度目标。**

1. 自动测速先检查同一参考配置的重复对局。事件不一致、异常、回退、缓存或资源中断时，停止后续比较并保留原设置。仅一次重复的预览不自动采用配置。
2. 事件比较仅对已识别的同一控制者、同一次阻挡声明排序完整的逐攻击者语句，保留每个阻挡列表内部顺序、牌名、实例编号、目标及重复项。混合控制者、不完整和未知格式保持原样；伤害、独立事件顺序及真实阻挡变化仍严格比较。
3. 界面说明停止原因。旧报告缺少新检查信息时仍可查看；此前有效配置保持兼容。便携版验收新增“参考不稳定不得采用”和“显示顺序与实例变化分别判断”检查。

### Risks / Next actions

这是自动测速可靠性修复，不是 Cube 胜率或原生引擎加速结论。24 局、每种实现两个批次不足以确认普遍性能优势；原始旧参考存在变化，不能把同批候选相等解释为长期确定性。后续仅对有剖析依据且通过预设门槛的候选继续独立实测，保留未通过记录。

### Artifacts

本地私有研究目录新增 empty-copy-trial、empty-copy-native（协议、源码快照、原始日志、摘要及独立审计）、reference-regression-before.xml、full-tests-026.xml、test-source-freeze-026.json 及 ui-reference-026-v2/receipt.json。公开回归位于 test_calibration_reference.py、test_native_event_comparison.py，公开便携验收位于 verify_portable_release.py。研究日志、实验类和个人信息不随发布分发。

## 0.2.8：不要把未来再版日期当作卡牌首次发行日期

### Problem

旧筛选将快照印张的 released_at 与当天比较，导致已有纸质版的旧牌因未来再版被排除。例如 Mind Stone 的快照采用 2026-11-09 的 mbc 印张，但 Scryfall 记录存在 1997-06-09 的 Weatherlight 纸质印张。需要恢复已有牌的正常候选资格，同时继续拦截没有已发售依据的未来牌。

### Inputs

本地 31,070 张快照中发现 30 张 Commander-legal 牌采用未来印张日期。逐一查询官方 api.scryfall.com 的相同 Oracle ID 印张列表，按发行日期升序；核对英文牌名、Oracle ID、纸质属性、非数字/非超大牌及过去日期，保存全部原始响应与校验值。所有 30 张均找到过去纸质印张。这里需要一个已发行印张作为依据，不声称计算了完整发行史或自动更新合法性。

例：[Mind Stone 的纸质印张记录](https://api.scryfall.com/cards/162e81d3-6cd4-4cb8-8ed8-cfbd8d34ca71)。Scryfall 网页文档曾返回 403；使用其公开 API 的正常 JSON 请求成功，没有关闭安全验证或使用第三方转发。发行商的 [2022 年复刻牌表](https://media.wizards.com/2022/downloads/card-sets/BRO_Cardlist_11102022.pdf) 也列有 Mind Stone。

### Checks performed

- 修复前，Mind Stone、Chaos Warp、Fellwar Stone 的新回归均复现未来日期误排，三个失败保留。
- 新旧筛选逐项比较七种设置、共 217,490 个牌张/设置组合：变化仅为五个 Bracket 档位各 30 个日期原因被移除，其他排除原因原样保持。默认每档 29 张恢复完整候选资格；Perch Protection 仍因额外回合偏好被排除。
- 固定 15 套、每档三种种子的新 Cube 均通过 600 张严格审计；300 桌、900 副轮抓牌组均可组为 60 张，颜色身份和 Bracket 检查通过，保持默认排除 {C} 支付需求和独立无色指挥官的偏好。
- 明确锁定 Mind Stone 与 Chaos Warp 另建一套 600 张 Cube，严格审计通过；30 张记录的牌名均能在本地 Forge 脚本索引中解析。索引解析不等于每张都经过完整对局。
- 两套预定新牌表各取第一桌、每桌三局换座，共 6 局原生 Forge 诊断全部正常、无缓存或回退。Mind Stone 在其中两局实际施放。第一次尝试因完整堆/原生余量/系统预留不足，在零局时停止，保留记录；回归进程结束且重新测得内存足够后，以相同六个输入和相同预算运行，没有替换失败对局。
- 独立复核六局原始日志、结果、种子、座位、牌组及源码摘要。完整源码回归 553 项通过。缺失/篡改证据、牌名或 Oracle ID 不匹配、数字版、未来日期和禁牌偏好均有检查；第一轮定向回归因历史断言文本/旧自定义例外不符合新统一检查而失败，原报告保留。

### Findings

问题出在印张日期与牌张可用性的混淆，并非强度评分太低。恢复的牌仍须通过赛制合法性、禁牌、快法术力、{C}、系列、年份、价格和强度检查。原本的快照印张字段没有改写为旧印张，目录签名、Oracle 角色标签和模型特征保持不变。

### Decision

**go：发布 0.2.8。** 新增可离线核验的 paper_release_witnesses.json，按精确牌名与 Oracle ID 绑定已发行纸质印张，固定校验值。文件丢失、修改或记录不匹配时不能据此放行；打包时缺失或修改直接失败。构筑过程不联网，合法性继续使用本地快照，不用发行依据覆盖禁牌和偏好。

未来日期没有可信旧印张依据时，所有构筑模式均拦截，包含旧自定义模式；修复了该模式原先跳过日期检查的例外。轮抓缓存签名和组牌实验源码快照包含证据模块及数据，避免使用旧筛选结果。组牌实验记录版本为 deck-policy-study-6。

便携包加入固定发行依据和新运行时检查，并补带 0.2.7 的无色费用报告。维护工具 `python -m cube_ai.tools.verify_paper_releases --out 全新目录` 只采集公开印张证据，不自动改写应用数据或校验值。

### Risks

这 30 条是对当前异常印张的核实，不是全牌库完整发行史。今后快照出现新的未来再版，需要用同一流程补充核实。系列/年份仍按快照印张字段筛选，没有自动切换印张；价格也继续来自原快照。六局属于两桌诊断，不证明胜率、各色组强度均衡或人类娱乐性改善；没有把它们加入训练语料。

### Next actions

继续按真实轮抓和对局数据检查行动密度、终结和色组差异；只对有依据的候选调整默认策略。发行依据更新保持独立、可审计，不混入评分模型训练。
