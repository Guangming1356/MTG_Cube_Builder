# 0.2.22：统一换牌反馈的色组口径

轮抓机器人有预先指定的偏好色组，但实际选出的指挥官可能是单色或其他颜色。此前牌组结构缺口按轮抓偏好归组，Forge 胜负却按最终指挥官颜色归组；模型把两者合在一起时，可能把不同牌组的表现当成同一组证据。

对外的实战汇总继续按最终指挥官颜色报告。换牌反馈另外记录轮抓偏好下的出场、胜场和平局，并把该统计与按相同偏好归组的结构缺口结合。无法确定偏好的历史记录不猜测归属；缺少该统计时使用中性的色组压力。旧报告和对局不覆盖。

重算 36 局既有 Forge 对局的 108 个席位，其中 21 个席位的偏好与最终颜色不同；新口径对 108 个席位均可归组。764 项自动测试通过。测试仅检验归组一致，不证明色组胜率或换牌质量提高。单色指挥官和实际颜色统计均保留。

# 0.2.21：修复 Forge 日志中的牌名识别

Forge 的施放记录与替代效应、区域变化、产法术力等信息可能连续出现。旧解析器会把这些后续记录拼到施放事件中，使一部分已施放牌无法匹配名称，进而低估该牌及终结手段的施放次数。现在在分析对局反馈时将这些辅助事件作为边界，同时继续支持换行折开的牌名。用于历史对局指纹的原始事件流保持不变。

用先前保留的 36 局真实 Forge 日志比较：1,348 条施放记录中，牌名可匹配数由 1,208 条增至 1,348 条；统计到的终结牌施放从 205 次修正为 234 次。108 位玩家中 81 位的牌名计数发生变化，施放总数、回合数和早期施放周期保持一致。这是对同一批日志的重新解析，不是新增对局，也不能说明胜率或牌力提高。

因为历史训练的终结牌标签可能受影响，实战模型版本升级为 `activity-7`。旧模型、反馈和日志保留；旧模型不会自动用于新版本，可以基于保留的已验证原始对局重新训练，并继续按原有验证门槛决定是否启用。共 762 项回归通过。

# 0.2.20：减少起手准备度的重复计算

起手测试中，已抽到的牌和可用法术力来源只会增加，每回合允许的地牌数量也不会减少。因此，一旦某张咒语可施放，当前模型之后的回合仍满足条件；程序可以直接记录后续回合，避免重复检查。

三种模式分别以 200 桌、三次交错计时：Bracket 3 Commander 中位 1.676 → 1.595 秒，自定义 Commander 1.675 → 1.639 秒，传统 Cube 1.738 → 1.601 秒。对应模式的完整压力测试报告逐项一致；对 90 副实际轮抓牌组、四种采样量和三种起始生命，共 1,080 组测试，结果及随机数状态全部一致。200 桌的 Python 跟踪分配峰值为 320,886 → 321,021 字节。

另一方案尝试缓存抓牌时的固定评分；传统 Cube 计时略慢，跟踪分配峰值从 320,526 升至 481,668 字节，因此没有采用。上述速度是本机压力测试的测量，不代表完整生成器或 Forge 对局同等提速。模型的假设和计算结果没有改变。

# 0.2.19：特殊施放费用的估算

部分咒语除牌面法术力费用外，施放时还有额外费用。构筑器识别部分明确的额外法术力费用、waterbend，以及“支付资源或支付法术力”的二选一费用，并将其纳入轮抓曲线和起手可施放性估算。

牌面法术力值、费用及导出不变。估算假设用法术力支付所识别的费用；waterbend 实际上也可以横置生物和神器协助，二选一费用也可以选择其他资源。因此估算不是牌的规则法术力值，也不表示实战必须支付这么多法术力。额外费用中的 X 按 1 估算；可选费用和其他未识别的资源费用不计入。

例如 Benevolent River Spirit 的牌面费用是 {U}{U}，施放时还需要 waterbend {5}。计算曲线时，在不考虑生物或神器协助的条件下按总计 7 点资源估算，但它的法术力值仍为 2。卡牌详情与报告会显示相应说明。

这是启发式近似，不支持所有额外费用、替代费用或具体对局中的资源；请结合真实轮抓和对局结果判断。更新特征版本后，旧版个人偏好模型仍会保留，但不再自动应用于不兼容的新特征；已有反馈可用于重新训练。

规则参考：[Avatar: The Last Airbender 发行注记](https://magic.wizards.com/en/news/feature/avatar-the-last-airbender-release-notes)。
