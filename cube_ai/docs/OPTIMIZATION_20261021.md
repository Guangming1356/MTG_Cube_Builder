# 2026-10-21 优化续报

## Problem

继续此前的速度、内存、游戏体验与简单界面优化。本次恢复时，原后台已停止：12 套固定采样中前八套完成，第九套仅保存六桌组牌，没有对局日志或完成记录。另检查到自动评分选回 CPU 后，GPU 资源仍可能驻留。

## Inputs

- 原 12 套、每套 20 桌三局换座的采样协议，共计划 720 局；保持牌表、种子、组牌方式和异常/跳过规则。
- 已验证的模式说明兼容组件、原 Forge JAR 和当前牌库。
- NVIDIA GeForce RTX 5060 Laptop GPU，使用实际 CUDA 运行检查资源释放和数值一致性。

## Checks performed

恢复第九套前，重新按固定输入构造它已保存的六桌，18 个牌组文件逐字节相同；牌库身份一致，且没有任何已完成对局被重跑。原中断目录和原任务编号保留，另存恢复收据；前八套直接使用原完整结果。当前采样继续执行全部固定预算，结束后统一学习，再进行已冻结的机器测速。

任务历史改为在计算开始前保存简短索引。重新启动时，未结束任务显示“上次运行中断”，附最后进度和已保存对局的下载入口；已经完成但来不及登记的结果也能重新找到。通过进程创建身份核对活跃拥有者，避免把 PID 重用或其他仍在运行的后台误当成自己的旧任务；不会附着或结束它们的进程。子任务不扫描或修改父后台历史。保存任务文件失败时立即说明原因，不留下永远排队的占位。

GPU 评分增加显式、可重复调用的关闭流程：初始化/编译失败、数值校验失败和进程退出均释放自身资源。自动模式选择 CPU 且没有已验证更快的 GPU 形状时，释放 CUDA 上下文、模块和显存缓冲；已记住的 CPU 选择无需重新初始化 GPU。其他形状仍能从 GPU 获益时保留其上下文。

## Findings

实际 31,070 × 48 × 32 评分矩阵中，GPU 仍未胜过 CPU：本次复核 CPU 中位约 0.67 毫秒，GPU 含传输约 2.01 毫秒，最大绝对误差约 0.0000076，在原容差内。关闭评分上下文后，设备空闲显存恢复到测前值，观测释放约 110 MiB；后续同类自动评分走 CPU，确认没有重新创建 CUDA。设备空闲显存属于全局观测，其他应用仍可能带来噪声。此前的原型测量保留，没有覆盖。

完整回归 **319 项通过**，约 70.79 秒，包含进程中断恢复、完成结果懒加载、活跃拥有者不变、存储失败不占位、GPU 失败清理及已缓存 CPU 路径不重新初始化等检查。测试不使用个人 AI 账户或外部付费接口。

## Decision

**go：采用任务历史恢复和 GPU 资源清理。** GPU 根据实测选择，不强行承担规则结算。当前活动游戏的牌表和组牌策略没有改变；默认组牌仍保留之前通过结构检查的单卡质量方案。

模型是否启用和新的内存配置是否能加速，仍等固定采样与原生对照结果；不在数据尚未完成时宣称强度或速度提升。

## Risks

- 中断任务可以找回记录，但普通历史恢复不会自动重跑尚未完成的游戏；本次第九套由明确的零完成记录和逐文件核对支持恢复，不能推广为任意任务已支持自动断点续算。
- 原模型依然按引擎身份隔离；新引擎数据未通过原独立验证门槛时使用固定评分。
- 显存释放检查不等于 Forge 对局加速，正常案例检查也不保证所有未来卡牌。
- 源码回归不等于真正便携包验收。远端同步与新版发布仍需恢复正常 GitHub 访问。

## Next actions

完成余下固定采样、统一模型验证和后续原生测速；空闲时重开主服务，检查真实界面的中断记录、当前模型状态和配置恢复，再整理源码与发布材料。
