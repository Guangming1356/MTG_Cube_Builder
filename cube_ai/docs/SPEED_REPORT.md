# 运行加速与实战学习验收

## Problem

在保留 Forge 真实规则结算、原生 AI、轮换座位和独立验证的前提下，减少构筑助手的等待时间。GPU、缓存和学习模型都要有独立对照，避免仅因组件更复杂便默认启用。

## Inputs

- Windows 本机：24 个逻辑处理器、约 32 GB 总内存、NVIDIA GeForce RTX 5060 Laptop GPU；空闲资源会随其他任务变化。
- Forge 2.0.15、Java 21；原有 600 张 Bracket 3 验证牌表。
- 历史实战去重并排除异常后：278 局、98 组不同的三副牌组合，来自 10 个 Cube 版本。
- 新增的 resident-1 Java 桥接、NumPy 批量评分、可选 NVRTC/CUDA 后端、版本化 SQLite 缓存，以及 activity-3 专用行为评分模型。

## Checks performed

1. 同一批 2 桌、6 局，分别运行原版逐局启动、常驻单进程、常驻三路并行。速度对照关闭比赛结果缓存。
2. 对所有正常对局逐条比较完整游戏事件序列，仅去掉实际耗时字段；比较全部玩家的回合、施放、异能、伤害和败因统计。引擎 API 缺失提示由 Forge 按 JVM 去重，另比较整轮提示集合。
3. 比较 20 桌新旧轮抓和组牌：保留开局抽样时结果完全一致；候选搜索省略未被使用的开局抽样后，抓牌、指挥官、主牌、地牌、基本地分配仍一致。
4. 比较 CPU 标量评分与批量评分；GPU 在实际卡池规模和更大合成矩阵上运行，检验数值误差并计入数据传输耗时。
5. 用真实对局训练均值/规则基准、岭回归、仅本方牌组特征的消融模型和小型神经网络。只用验证集选模型，测试集用于最终采用判断。
6. 跑通小样本的“训练 → 提出替换 → 冻结 → 新旧独立验证 → 导出”流程。原版保留，新版严格审计通过；因样本不足，正确保留为实验候选。
7. 本轮最终回归 **211 项通过**，网页脚本与新增 Python 模块语法检查通过。另验证了缓存失效、GPU 结果错误回退、模型数据分组、坏模型拒绝和跨阶段常驻内存预算。

## Findings

### 对局速度

| 相同的 6 局 | 总耗时 | 正常完成 | 原生引擎异常 |
|---|---:|---:|---:|
| 原版逐局启动，单路 | 177.166 秒 | 5 | 1 |
| 常驻 Forge，单路 | 109.046 秒 | 5 | 1 |
| 常驻 Forge，三路并行 | 70.456 秒 | 5 | 1 |

本次对照中，常驻单路约快 1.62 倍，常驻加并行约快 2.51 倍。十次正常对局的比较中，游戏事件序列与玩家行为统计均一致。异常是同一个既有 Forge 原生 AI 问题，三种方式均保留为引擎错误。常驻进程发生异常后被替换，下一局正常运行。

最初的严格比较将“每 JVM 只打印一次的 API 提示”也按每局比较，导致一个假失败。原报告保留；复核完整游戏事件、全部玩家行为及整轮提示集合后通过，另保存 validation-v2.json，没有删除原始证据。

### 轮抓、缓存和候选筛选

- 原轮抓实现 20 桌约 1.037 秒；减少重复扫描后，保留原开局抽样约 0.781 秒。
- 结构评估首次计算并写入缓存约 0.839 秒；完全相同输入命中缓存约 0.039 秒。命中场景约快 26.7 倍，首次计算没有同等幅度的收益。
- 缓存包含代码、规则和资料版本、牌库签名、构筑参数、随机种子、色组偏好与整套开包布局。仅凭“上次没抓到这张牌”不能复用结果。
- 原候选筛选会为许多最后不会评估的替换提前审计整套 Cube。现在先批量排序，轮到候选时再严格审计；不合规的候选不占开发评估预算。每次采用和最后导出仍有严格审计。
- 比赛缓存只保存正常完成的正式结果与原日志；异常不缓存。版本、后端、牌组文件、座位顺序、种子和时限参与匹配。缓存命中明确标注为复用，不是新增实战样本；独立验证继续使用预先声明的新种子。外部自定义 Forge 默认不复用比赛缓存。

### GPU

GPU 内核已在本机真实运行。31,070 行 × 48 特征 × 32 输出的比较中，最大绝对误差约 0.0000077，在既定容差内。CUDA 包含传输、计算和结果取回，不能仅用内核时间冒充端到端收益。

当前实际候选评分矩阵较小：CPU 批量计算约 0.6 毫秒，GPU 约 1 毫秒；更大的合成测试中，本机这套轻量内核也没有胜过 NumPy。默认自动模式据实选择 CPU，用户仍可尝试 GPU。组件或驱动不可用、数值检验失败时，记录原因并回退 CPU。GPU 不承担 Forge 的规则结算。

### 专用评分模型

学习目标为实测的三类行为：前四个完整个人回合周期的主动行动、每回合施放密度、本局是否施放终结牌。一个周期从自己的回合开始至下一次自己的回合开始，计入期间任意回合的施放、主动异能和宣攻；不计自动触发与下地。最后未完整观察的周期会被排除；任一玩家不足四个完整周期的整局不训练，并单独记录数量，这可能少代表结束很早的牌组。旧版 activity-2 只统计自己回合的施放，保留旧报告但不直接启用旧模型。不把单局胜负平均分配给单卡，也不把行为活跃直接叫作牌组强度。

同一三副牌组合的所有座位、重复种子和旧/新 Cube 中完全相同的牌组不会跨训练和测试。Cube 与牌组的关联按连通分量整体划分；无法同时做到时明确标记为仅按牌组分组。

本轮真实训练中，验证集选择了小型神经网络，但保留测试损失约 0.06843，均值基准约 0.06229，模型反而较差。因此模型已保存、未启用。自动采用还要求至少 500 局、100 组独立牌组、20 组测试牌组、整 Cube 与牌组保留、超过最强简单基准至少 3%、损失差的整桌重采样区间上限小于零，以及主要活动预测也优于基准。

## Decision

**go：默认启用已验证的常驻 Forge、有界并行、版本化缓存和批量评分。GPU 自动按实测选择。学习模型本轮不采用。**

- 常驻 Forge 每次创建全新的比赛，明确重设种子；错误、超时或完成 16 局后重建进程。启动失败可回退原版逐局运行。
- 一轮训练、筛选和独立验证共用已分配的资源预算，避免常驻进程已占用的内存让下一阶段误报“并行数过高”。结束后回收所有自建 JVM。
- 当前轮开始时冻结学习模型；本轮结束后的数据只用于更新下一轮模型，不回头调整已经验证的候选。
- 分享包只包含源代码、已验证桥接类和可选 CUDA 运行组件，不包含本机模型、缓存、牌组、对局、偏好或登录资料。

## Risks

- **monitor：速度受机器和比赛影响。** 6 局对照是可复现的小样本速度验收，不能承诺所有 Cube 都快 2.5 倍。首次启动、长局和原生 AI 缺陷仍会耗时。
- **monitor：GPU 不一定更快。** 小矩阵、数据传输和初始化可能抵消收益，自动模式保留 CPU。
- **monitor：模型证据不足。** 本轮学习模型未超过基准；程序没有用差模型替换现有评分。活动指标也不能认证强度、均衡或娱乐性。
- **accepted risk：原生 Forge 差异。** 常驻方式验证的是当前固定版本及桥接代码；二进制或桥接变化使验证签名失效，回退原版入口。
